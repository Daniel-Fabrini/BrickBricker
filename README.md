# Brick Breaker Infinite

A complete, offline, mobile-first brick breaker for Android (portrait), built with **Phaser 3**,
**TypeScript (strict)**, **Vite** and **Capacitor**. Two game modes, two gameplay styles, two visual
themes, endless validated levels, strategic power-ups, local saves, achievements, cosmetics and
three languages.

- **Modes:** Progression (endless levels, checkpoints every 5 levels, no game over) and High Score
  (five lives, up to nine with Extra Life).
- **Styles:** Classic (paddle, ball, bricks) and Maze (walls and corridors, later moving sliders
  and timed gates).
- **Themes:** Retro (pixel art, chiptune) and Neon (glow, synthwave). Purely visual.
- **Languages:** English, Spanish, Brazilian Portuguese (auto-detected, switchable at any time).
- No accounts, no network, no ads, no analytics, no purchases.

## Quick start

Requirements: **Node.js ≥ 22.12** (Capacitor 8 CLI needs Node 22) and npm.

```bash
npm ci                 # install exact locked dependencies (.npmrc sets legacy-peer-deps)
npm run dev            # dev server on http://localhost:5173 (use the browser's mobile emulation)
npm run build          # type-check + production build into dist/
npm run preview        # serve dist/ on http://localhost:4173
```

Quality checks:

```bash
npm run typecheck      # tsc --noEmit (strict)
npm run lint           # ESLint (typescript-eslint)
npm test               # Vitest unit + gameplay tests
npm run test:e2e       # Playwright end-to-end tests (builds and serves dist/ automatically)
npm run check          # typecheck + lint + unit tests + production build
```

`npm run test:e2e` uses Playwright 1.56 (Chromium). On a fresh machine run
`npx playwright install chromium` once.

## Android build

Prerequisites:

- JDK **21** (`java -version`).
- Android SDK with **platform 36** (`platforms;android-36`), **build-tools 36.x** and
  **platform-tools**. Either install Android Studio (Narwhal/2025.x or newer, which ships AGP 8.13
  support) or the command-line tools:
  `sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"`.
- `ANDROID_HOME` (or `android/local.properties` with `sdk.dir=...`) pointing to the SDK.

The native project lives in `android/` (generated by `npx cap add android` and customised: portrait
lock, dark launch theme, generated launcher icons and splash images, version 1.0.0). The web build is
copied into it by `cap sync`.

```bash
npm run cap:sync                       # npm run build + npx cap sync android
npm run android:open                   # open in Android Studio (Run ▶ on a device/emulator)
npm run android:debug                  # build dist, sync, ./gradlew assembleDebug
#   -> android/app/build/outputs/apk/debug/app-debug.apk
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
npm run android:release                # ./gradlew bundleRelease (configure signing first)
```

For a store release add a signing config (keystore) to `android/app/build.gradle` or sign the AAB
in Android Studio (*Build → Generate Signed App Bundle*). Keystores are git-ignored.

Verified in this repository's CI-like environment (JDK 21, SDK platform 36, build-tools 36.0.0,
Gradle 8.14.3 wrapper, AGP 8.13): `./gradlew assembleDebug` produces a ~4.9 MB `app-debug.apk`
(`com.brickbreaker.infinite`, versionName 1.0.0, minSdk 24, targetSdk 36, portrait).

Troubleshooting: if Gradle fails with HTTP 429 from `repo.maven.apache.org`, retry, or add a
user-level init script (`~/.gradle/init.d/mirror.gradle`) that prepends Google's Maven Central
mirror `https://maven-central.storage-download.googleapis.com/maven2/` to the repositories.

Min SDK 24 (Android 7.0), target/compile SDK 36. The status bar is hidden during play; Capacitor's
`SystemBars` plugin injects `--safe-area-inset-*` CSS variables so the layout avoids display
cutouts and the navigation bar on edge-to-edge devices.

## Controls

- **Move:** swipe anywhere on the screen; the paddle follows your finger horizontally. You never
  need to touch the paddle. A desktop mouse also works (hover to move).
- **Control assist (on by default):** the outer ~7% of the screen width already maps to the walls,
  so you can reach the edges without dragging onto the system back-gesture area.
- **Relative drag (Settings):** the paddle moves by your finger's displacement instead of jumping to
  it.
- **Launch:** automatic. The ball rests on the paddle for ~1 s (a ring shows the countdown) and then
  launches by itself.
- **Powers:** tap one of the two inventory slots below the playfield. Powers never activate on their
  own.
- **Pause:** the pause button (top right) or the Android back button. The game also pauses
  automatically when the app goes to the background and only resumes when you tap **Resume**.

## Gameplay rules

### Progression
- Levels continue forever. All destructible bricks must be destroyed; walls and steel blocks never
  count.
- Completing level 5, 10, 15, 20 … creates a **checkpoint**. A checkpoint stores the completed
  milestone, the score and both inventory slots at that moment; play resumes at milestone + 1.
- Losing the last ball fails the attempt: you return to the most recent checkpoint (level 1 with an
  empty inventory before the first checkpoint), with the checkpoint's score and inventory.
- Best level, highest checkpoint and every checkpoint snapshot are kept forever per style. A new
  session can start from any unlocked checkpoint.
- Extra Life never drops in Progression (there are no lives).

### High Score
- A run starts with **5 lives**. Losing one ball while others are still in play costs nothing; losing
  the **last** ball costs exactly one life and serves a new ball.
- **Extra Life** (rare drop) adds one life, never beyond **9**. Caught at the cap it gives 500 points
  instead, and it is not dropped at all while you are at the cap.
- The run ends when no lives remain; the final score and run statistics are shown and the best
  score per style is saved. Failed runs never touch Progression data.
- Each run uses a fresh level seed, so generated layouts vary between runs.

### Bricks
| Brick | Hits | Score on destruction |
| --- | --- | --- |
| Standard | 1 | 10 |
| Resistant (2–5 hp, shows remaining-hp pips and cracks) | hp | 10 × max hp, plus 2 flat points per non-destroying hit |
| Special (gold “?” / diamond; 1–2 hp) | hp | 25, may drop a power (85%) |
| Wall / steel | indestructible | – (never counted for completion) |

Destruction points are multiplied by the level multiplier (1 + 5% per level, max ×3) and the combo
multiplier. Damage hits are never multiplied, so repeated hits cannot be farmed.

### Combos and bonuses
- Every destruction within **3 s** of the previous one extends the chain. The multiplier grows by
  ×0.5 every 5 chained bricks (×1 → ×1.5 → ×2 …) up to **×4**. The timer only runs during active
  play (not while the ball rests on the paddle, nor while paused).
- **Burst:** +15 for each brick destroyed within 0.35 s of two others.
- **Power kill:** +5 for each brick destroyed by Explosion or Piercing.
- **Level clear:** 100 × level number.

### Power-ups
Drops come only from special bricks: weighted random **Multiball 34 / Piercing 30 / Explosion 30 /
Extra Life 6** (Extra Life only in High Score, max one per level). A drop falls straight down and
must be caught with the paddle; a missed drop disappears. At most four drops are on screen.

- **Multiball:** up to three existing balls each split into two more (seeded angle jitter so every
  ball has its own trajectory); hard cap 8 balls. Refused (and kept) when already at the cap.
- **Piercing (7 s, stacks to 14 s):** balls pass through destructible bricks, dealing 1 damage to
  each brick once per pass — resistant bricks still need all their hits. Walls still bounce.
- **Explosion:** arms a charge (max 2). The next brick a ball touches detonates: bricks within 36
  units take 2 damage, within 56 units 1 damage. Hit points are always respected.

**Inventory:** exactly two slots. Catching a power fills the first free slot; with both slots full the
new power is *not* stored (a small 50-point consolation) and nothing is replaced. Both stored powers
carry over between levels. High Score clears the inventory only when a new run starts; Progression
restores the checkpoint's inventory after a failed attempt. Uncaught drops are discarded at level end.

### Ball physics and assistance
- Custom deterministic physics: 120 Hz fixed steps with sub-steps (≤ 3 units per sub-step, so no
  tunnelling), circle-vs-cell collision, seam-aware corner handling between neighbouring cells.
- Paddle rebound angle depends only on the hit position: up to 62° from vertical at the edges,
  near-vertical at the centre (min 3° so rallies never freeze).
- Every bounce keeps |vy| ≥ 32% of speed (no near-horizontal paths). Ball speed per level rises from
  300 to at most 470 units/s; absolute cap 560 units/s (the field is 600 units tall).
- **Inactivity speed-up:** after 8 s without destroying a brick the speed rises smoothly (+2.5%/s, max
  ×1.3, never above the cap); after a destruction it returns smoothly (−12%/s).
- A ball that neither touches the paddle nor damages a brick for 10 s receives a small angle nudge;
  a ball squeezed by a moving obstacle is relocated to free space.

### Ball accounting
A ball counts as **launched** when it is served from the paddle (level start or after a lost
life/attempt) or created by Multiball. Bounces and balls restored from a save never count. Lives are
only charged when the last active ball is gone, exactly once per loss.

### Difficulty and levels
- `src/config/difficulty.ts` combines brick rows, density, resistant ratio, maximum hit points,
  special-brick count, formation complexity, maze complexity and ball speed. Speed only rises between
  five-level tiers, rows grow every ~2 levels, hit points unlock at levels 3/9/18/30, and the first
  level after each checkpoint is a lighter “breather”. No level raises every parameter at once.
- **Maze:** levels 1–5 ledges/pillars, 6–12 pockets/shelves/chambers, 13+ corridors and crossroads,
  16+ moving sliders, 22+ timed gates (with a flashing warning before closing). Gates never close on a
  ball and are never the only route to any brick.
- **Procedural generation** is seeded by (style, level, seed) and constraint-based: every candidate is
  validated (grid bounds, no overlaps, slider lanes clear, ≥ 150 units of free space above the paddle,
  and a configuration-space flood fill proving every destructible brick is reachable through
  corridors wide enough for the ball, with gates treated as closed). Failing candidates are rebuilt;
  a safe fallback exists.
- **Special levels:** 16 hand-designed layouts (8 Classic, 8 Maze) on every 10th level. When the set
  is exhausted it repeats mirrored with tougher bricks, so the game is endless.

## Screens and flow

Main menu (animated attract-mode playfield behind it): Continue/Abandon banner for an unfinished
game, the two mode cards (best level / checkpoint / best score), Classic/Maze and Retro/Neon toggles,
and Stats, Awards, Collection, Language and Settings. In game: HUD (score, level, lives or checkpoint,
level progress bar, combo), two power slots and an effect indicator. Overlays: pause (with power
help), level complete (with checkpoint banner), attempt failed, game over / new record. Achievement
and cosmetic unlocks appear as small non-blocking toasts.

## Persistence

- One versioned JSON document (`bbi.save`) holds settings, the profile (records, per-style
  progression and checkpoint snapshots, statistics, achievements, cosmetics) and the unfinished
  session. On Android it is stored in Capacitor Preferences (SharedPreferences) and mirrored to
  WebView localStorage; on the web, localStorage.
- Each write is a single atomic key update with a checksum; the previous good document is kept as
  `bbi.save.backup`. Corrupted saves fall back to the backup, otherwise start fresh (the unreadable
  text is kept under `bbi.save.corrupt`).
- Loading migrates older versions (`src/persistence/migrations.ts`) and sanitises every field;
  permanent data is repaired field by field, while an invalid unfinished session is dropped entirely.
- The game autosaves every 4 s of play and immediately on pause, backgrounding, level transitions and
  quitting. **Continue** restores the exact simulation (balls, bricks, timers, combo, speed boost,
  RNG state, collectibles, inventory, lives, score) and resumes paused. **Abandon** clears only the
  unfinished session.
- Because statistics and the session are saved in the same atomic document, restoring a session can
  never replay already-counted events.

## Achievements and cosmetics

33 achievements (progression milestones, checkpoints, High Score thresholds and records, brick
totals, combos, each power, Maze, special levels and 6 secret ones with hints). They are derived
from statistics only and unlock 15 cosmetics: ball skins, paddle skins, trails and brick-burst
effects. Cosmetics are visual descriptors; the simulation never receives them (verified by tests).

## Accessibility

Settings → Accessibility (all work in both themes and never change scoring, lives, drops or
progression):
- **Enhanced ball visibility:** high-contrast double outline and a short trail on every ball.
- **Tolerant paddle control:** steadier paddle follow, a small tremor dead-zone and wider edge assist.
- **Reduced effects:** fewer particles, no screen shake or flashes, no shimmering bricks.

`prefers-reduced-motion` also shortens UI animations.

## Audio

All sound effects and both music loops are **synthesised at runtime with the Web Audio API** – no
audio files, no licensing concerns. Retro uses pulse/triangle/noise chiptune voices; Neon uses
filtered saw/sine voices with echo. Separate music/effects volume and on/off settings. Effects have
per-sound retrigger limits and a 12-voice cap (no multiball noise). Music ducks and effects mute
while paused; the audio context is suspended in the background.

Fonts: *Press Start 2P* and *Orbitron* (SIL Open Font License, bundled via `@fontsource`, offline).
All graphics (bricks, balls, paddles, power icons, launcher icons, splash) are generated
procedurally; there are no third-party art assets.

## Localization

`src/i18n/locales/en.ts` defines every key; `es.ts` and `ptBR.ts` are typed as
`Record<TranslationKey, string>`, so a missing key is a compile error (and a unit test also checks
non-empty values and matching `{placeholders}`). First launch picks Brazilian Portuguese for any
Portuguese locale, Spanish for any Spanish locale, English otherwise. Changing language never resets
the game.

## Architecture

```
src/
  config/        tuning.ts (all gameplay constants), difficulty.ts (difficulty curve)
  core/          pure TypeScript gameplay – no Phaser, no DOM
    level/       grid, formations, maze templates, generator, validator, special levels, provider
    sim/         GameSimulation (physics, collisions, bricks, powers, scoring, combos, speed,
                 mode rules), events, state, inventory, drop table, fixed-step loop
    run/         cross-level rules: checkpoints, lives, inventory carry-over
    meta/        statistics, achievements, cosmetics
    input.ts     touch → paddle mapping (direct/relative, assist, tolerant)
  game/          GameSession (one Progression session / High Score run + profile updates)
  persistence/   schema, validation, migrations, storage adapters, SaveManager
  i18n/          translations and helpers
  audio/         AudioEngine, synthesised SFX and music
  render/        Phaser GameScene, procedural sprite painter, themes
  ui/            DOM menus, HUD, overlays, layout/safe areas
  platform/      Capacitor lifecycle/back button, storage factory, haptics
  app/           App shell (boot, navigation, settings) and GameController (loop, input, feedback)
tests/           Vitest unit and gameplay tests
e2e/             Playwright end-to-end tests
android/         Capacitor Android project
```

**Why custom physics instead of Phaser Arcade?** The simulation must be deterministic and fully
serialisable (exact Continue, reproducible tests, no double-counted statistics), must never tunnel at
high speed, and must run headless in unit tests. Phaser is used for what it does best – rendering,
the frame loop, textures, particles, tweens and camera effects – while all rules live in
`src/core` and communicate with rendering/audio/UI only through `SimEvent`s.

Menus and the HUD are DOM (crisp text in all languages, accessible buttons, easy automated testing);
the playfield is a single Phaser canvas scaled to the device pixel ratio (capped at 2.5).

### Test hooks

Appending `?test` to the URL exposes `window.__BBI__` (used by the Playwright suite: inspect state,
destroy all bricks, lose all balls, autopilot, flush saves). The packaged Android app never loads
such a URL. `?seed=N` fixes the High Score seed.

## Limitations

- Music and sound are procedural synth placeholders by design (original, license-free); there are
  no recorded audio assets.
- Physics uses discrete sub-stepped collision with corner heuristics; it is robust in testing but is
  not a general-purpose physics engine.
- Real-device testing (performance on low-end phones, haptics, cutout handling, Android lifecycle
  events) could not be performed in this environment: the debug APK was built and inspected, but it
  was not run on a phone or emulator (no hardware virtualisation available). The web build was
  exercised in headless Chromium with Pixel 7 and 360×640 emulation.
- The release build is unsigned until you add your own keystore.
- `npm audit` reports a moderate advisory in a transitive dependency of the Capacitor *CLI* (`uuid`
  via the iOS `xcode` package). It is a development tool only and is not part of the shipped app.
